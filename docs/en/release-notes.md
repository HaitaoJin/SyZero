# Release Notes

This page tracks framework updates for the VitePress site.

## v1.6.0

- **Gateway abstractions extracted into their own package | breaking change**:
  - The 11 types previously living under `src/SyZero.Core/Gateway/` (`IGateway` / `IGatewayConfigurationStore` / `IGatewayConfigurationApplier` / `GatewayConfiguration` / `GatewayRoute` / `GatewaySwaggerEndPoint` / `GatewayOptions` / `GatewayLoadBalancerOptions` / `GatewayRateLimitOptions` / `GatewayGlobalRateLimitOptions` / `GatewayConfigurationBackup`) are now shipped as the standalone package **`SyZero.Gateway.Abstractions`**, containing only interfaces and DTOs with no concrete gateway dependency.
  - `SyZero.Ocelot` is renamed to [`SyZero.Gateway.Ocelot`](/en/modules/SyZero.Gateway.Ocelot); `SyZero.YARP` is renamed to [`SyZero.Gateway.YARP`](/en/modules/SyZero.Gateway.YARP). Both depend on the new `SyZero.Gateway.Abstractions` plus `SyZero.Core`.
  - C# namespaces follow suit: `SyZero.Ocelot.*` → `SyZero.Gateway.Ocelot.*`; `SyZero.YARP.*` → `SyZero.Gateway.YARP.*`. **The abstraction namespace stays as `SyZero.Gateway`** (so existing `using SyZero.Gateway;` keeps working — you only need to switch any project that was depending on `SyZero.Core` to obtain these types so that it now references `SyZero.Gateway.Abstractions` or a concrete implementation package).
  - `SyZero.Gateway.Admin` no longer relies on `SyZero.Core` for `IGateway` / `IGatewayConfigurationStore`; it now depends on `SyZero.Gateway.Abstractions`.
  - `SyZeroOcelotOptions.CorsPolicyName` default `"SyZero.Ocelot"` → `"SyZero.Gateway.Ocelot"`; `SyZeroYarpOptions.CorsPolicyName` default `"SyZero.YARP"` → `"SyZero.Gateway.YARP"`. If your code references the old defaults via `app.UseCors("SyZero.Ocelot")` / `app.UseCors("SyZero.YARP")`, update accordingly (or set `CorsPolicyName` explicitly to keep the old value for backwards compatibility).
  - **Migration checklist**:
    1. In csproj: change `<PackageReference Include="SyZero.Ocelot" />` to `<PackageReference Include="SyZero.Gateway.Ocelot" />`; same for YARP.
    2. In source: `using SyZero.Ocelot;` → `using SyZero.Gateway.Ocelot;`; `using SyZero.YARP;` → `using SyZero.Gateway.YARP;`.
    3. Update reflection / string references accordingly (e.g. `Type.GetType("SyZero.Ocelot.OcelotConfigurationApplier")`).
    4. To preserve the old CORS policy names, set `CorsPolicyName` explicitly inside `AddSyZeroOcelot(...)` / `AddSyZeroYarp(...)`.
  - The complete xUnit suite still passes: **261/261**.

## v1.5.0

- **5 cross-cutting capabilities (core stability / service governance)**
  - **`SyZero.Core` multi-level cache (L1+L2 with cache-penetration / breakdown / avalanche protection)**: new `IMultiLevelCache` (`GetOrCreateAsync<T>` / `SetAsync<T>` / `RemoveAsync`) and `MultiLevelCache` default implementation (L1 = `IMemoryCache` in-process, L2 = `IDistributedCache`, plug any distributed cache). **Penetration**: `NullSentinel` caches null results; **breakdown**: `ConcurrentDictionary<key, Lazy<Task>>` SingleFlight collapses concurrent loads to one origin call; **avalanche**: `JitterRatio` adds randomized jitter to expirations. One-line registration via `AddSyZeroMultiLevelCache(...)`. `SyZero.Redis` now also registers `RedisDistributedCache` automatically as L2.
  - **`SyZero.AspNetCore` global exception + ProblemDetails (RFC 7807)**: `SyError` (`Code` / `Title` / `Detail` / `Type` / `Status`) + `SyBusinessException`; `SyExceptionMiddleware` translates business exceptions into `application/problem+json` responses (with `traceId`) and uncaught exceptions into `SY-500`. Wire up with `AddSyZeroExceptionHandler()` + `UseSyZeroExceptionHandler()`.
  - **`SyZero.Core` configuration hot-reload notifier**: new `IConfigurationChangedNotifier` (`event Changed`) + default `ConfigurationChangedNotifier` based on `Microsoft.Extensions.Primitives.ChangeToken` listening to `IConfiguration.GetReloadToken()`. Works with **any configuration source** (appsettings.json file watcher / Nacos / Consul / Apollo) without modifying the underlying provider. `AppConfig.GetSection<T>` already reads live values, no rebinding required.
  - **New module [`SyZero.Idempotency`](/en/modules/SyZero.Idempotency)**: `Idempotency-Key`-header-driven idempotency middleware. `IIdempotencyStore` (`TryReserveAsync` / `SaveAsync` / `GetAsync`) with default `MemoryIdempotencyStore`; the first request reserves the slot, the response body is buffered and persisted; subsequent requests with the same key **replay** the original response (StatusCode / ContentType / Body). Targets POST / PUT / PATCH / DELETE; concurrent duplicates while the first request is in-flight return 409. Swap for Redis / SQL stores in multi-instance setups.
  - **New module [`SyZero.DistributedTransaction`](/en/modules/SyZero.DistributedTransaction)**: Outbox pattern + simple Saga coordinator.
    - **Outbox**: `IOutboxStore` (`EnqueueAsync` / `FetchPendingAsync` / `MarkPublishedAsync` / `MarkFailedAsync`) with default `MemoryOutboxStore` (replace in production) and `OutboxBackgroundService` (`PollIntervalSeconds` / `BatchSize` / `MaxRetryCount` configurable) that polls and dispatches via `IEventBus.Publish`; messages exceeding `MaxRetryCount` retain the last error for manual handling.
    - **Saga**: `ISagaStep<TContext>` (`ExecuteAsync` / `CompensateAsync` / `Name`) + `SagaCoordinator<TContext>` runs steps in order; if any step throws, previously executed steps are compensated **in reverse order**, returning a `SagaResult { IsSuccess, Error?, CompensationErrors[] }`.
  - **Tests**: 9 new cases (`MultiLevelCacheTests` / `ConfigurationChangedNotifierTests` / `IdempotencyStoreTests` / `OutboxStoreTests` / `SagaCoordinatorTests`); full suite raised from 237/237 to **246/246 green**.

## v1.4.0

- **New module [`SyZero.MultiTenancy`](/en/modules/SyZero.MultiTenancy)**: tenant context + resolver middleware.
  - **`ICurrentTenant`** is Scoped and backed by `AsyncLocal<TenantInfo?>`; `Change(tenant)` returns `IDisposable` so background workers can flow context manually across `await`.
  - **`ITenantResolver`** with three built-ins (`HeaderTenantResolver` for header `__tenant`, `DomainTenantResolver` for sub-domain, `ClaimTenantResolver` for `tenantid` / `tenant` claims), tried in registration order; first match wins.
  - **`ITenantStore`** abstraction with `FindByIdAsync` / `FindByNameAsync`; built-in `InMemoryTenantStore` for demos / unit tests. Implement your own to plug into EF Core / SqlSugar / MongoDB.
  - **`MultiTenancyMiddleware`** runs all resolvers → calls `ITenantStore` → enters `ICurrentTenant.Change(tenant)` and restores on response end. Only `IsActive=true` tenants are accepted.
  - **`IMultiTenant` entity marker** with `long? TenantId`; wire `HasQueryFilter` against `ICurrentTenant` for single-database filtering.
  - **`ITenantConnectionResolver`** sharding hook (default reads `TenantInfo.ConnectionString`); replace with your own to route by tenant id to N shards.
  - **One-line wiring**: `builder.Services.AddSyZeroMultiTenancy(builder.Configuration)` + `app.UseSyZeroMultiTenancy()`; configuration section is `MultiTenancy`.
- **New module [`SyZero.BackgroundJobs`](/en/modules/SyZero.BackgroundJobs)**: in-memory background jobs backed by `System.Threading.Channels`.
  - **`IBackgroundJob<TArgs>`** contract + **`IBackgroundJobManager.EnqueueAsync<TJob, TArgs>(args)`** entry (Singleton); a fresh `IServiceScope` is created per execution and `TJob` is resolved as Scoped.
  - **`BackgroundJobChannel`**: bounded channel with default capacity 1024 and wait-on-full; opt-in `DropOldestWhenFull=true` for non-blocking drop-oldest semantics; `QueueCapacity=0` falls back to unbounded (local dev only).
  - **`BackgroundJobWorker : BackgroundService`**: configurable `WorkerCount` (default 1); job exceptions are `ILogger.LogError`-ed and swallowed — **other jobs keep flowing**; `OperationCanceledException` is propagated to honor graceful shutdown.
  - **One-line wiring**: `builder.Services.AddSyZeroBackgroundJobs(builder.Configuration, opt => ...)` + `services.AddBackgroundJob<TJob>()` to register each job; configuration section is `BackgroundJobs`.
  - **Not provided**: automatic retry / persistence / delayed / cron scheduling (planned in `SyZero.BackgroundJobs.Hangfire` / `Quartz` child modules).
- **New module [`SyZero.DistributedLock`](/en/modules/SyZero.DistributedLock)**: distributed lock abstraction + in-process default + Redis backend.
  - **`IDistributedLockProvider.AcquireAsync(key, expiration, waitTimeout, ct)`** returns `IAsyncDisposable?`: lock handle on success, `null` on timeout / cancellation; `waitTimeout=Zero` means "try once, no waiting".
  - **`LocalDistributedLockProvider`** (inside `SyZero.DistributedLock`): built on `SemaphoreSlim` + expiration `CancellationToken` for auto-release. **Single-instance / test only**.
  - **`RedisDistributedLockProvider`** (inside `SyZero.Redis`): `SET NX PX` for acquire + Lua script for token-checked release (**won't delete someone else's lock**); registered automatically as the default `IDistributedLockProvider` whenever `SyZero.Redis` is referenced — your business code is unaware of the backend swap.
  - **Idempotent release**: multiple `DisposeAsync` calls are safe; the expiration is the deadlock safety net, so even forgetting `await using` is recoverable.
- **Test coverage**: `src/SyZero.Tests/MultiTenancyTests.cs` / `BackgroundJobsTests.cs` / `DistributedLockTests.cs` add 6 cases. Full suite 187/187 passing.

## v1.3.0

- **New module [`SyZero.Authorization`](/en/modules/SyZero.Authorization)**: one-stop RBAC + JWT Bearer authentication / authorization built on ASP.NET Core Identity.
  - **Entities**: `User` / `Role` / `PermissionGroup` / `Permission` / `UserRole` / `RolePermission` / `UserPermission` / `RefreshToken`, all `: Entity` (`long` PK).
  - **Permission definitions**: `IPermissionDefinitionProvider` + `PermissionDefinitionManager` (singleton, lazily aggregates providers) with grouping / parent-child tree / sort / enable-flag; `PermissionSyncHostedService` upserts the in-code definitions into the database on startup (keyed by `Name`).
  - **Default `IPermissionChecker` → `RbacPermissionChecker`**: synchronous `IsHas(name)` — user-level overrides (`UserPermission.IsGranted`) win over role aggregation, **any explicit deny short-circuits**. Registration overrides the placeholder in `SyZero.Core`.
  - **JWT**: `JwtTokenManager : IToken` provides `CreateToken / GetPrincipal` (HMAC-SHA256, `ClockSkew=30s`, returns `null` on failure). `JwtOptions` is bound from both `Configuration.GetSection("Jwt")` and an `Action<JwtOptions>`.
  - **Refresh tokens**: `IRefreshTokenManager` + `RefreshTokenManager` — 32-byte `RandomNumberGenerator` + Base64Url; **only the SHA-256 hash is persisted**. `RotateAsync` detects replay (re-using a revoked token cascades into `RevokeAllAsync` and throws `SyMessageException`); `RevokeAllAsync(userId)` powers "log out everywhere".
  - **`SyZeroAccountManager`** (`IScopedDependency`): glues `UserManager<User>` + `IRefreshTokenManager` and exposes `LogoutAsync` / `LogoutAllAsync` / `ChangePasswordAsync` / `ResetPasswordAsync`. Successful password change / reset automatically calls `RevokeAllAsync` to force every device offline.
  - **Identity stores**: `SyZeroUserStore` (`IUserPasswordStore` + `IUserEmailStore` + `IUserSecurityStampStore` + `IUserPhoneNumberStore` + `IUserLockoutStore` + `IUserTwoFactorStore`) and `SyZeroRoleStore`, both backed by `IRepository<TEntity, long>`.
  - **One-line wire-up**: `builder.Services.AddSyZeroAuthorization(builder.Configuration)` + `app.UseSyZeroAuthorization()`. Internally calls `AddIdentityCore<User>().AddRoles<Role>().AddDefaultTokenProviders()` + `AddAuthentication(JwtBearer).AddJwtBearer(...)` + `AddAuthorization()`.
  - New NuGet dependency: `Microsoft.AspNetCore.Authentication.JwtBearer 9.0.0` (added to central package management in `Directory.Packages.props`).
- **`SyZero.Core` adds generic primary-key support (backward compatible)**:
  - New `IEntity<TKey>` / `Entity<TKey>` and `IRepository<TEntity, TKey>`. The existing `IEntity` / `Entity` / `IRepository<TEntity>` are kept by inheriting the `long`-keyed defaults — **no change required for existing code**.
  - `SyZero.EntityFrameworkCore` / `SyZero.SqlSugar` / `SyZero.MongoDB` providers are generalized accordingly, allowing `Guid` / `string` / composite primary keys.
- **Nullable return tightening (mildly breaking)**: `IObjectMapper.Map<T>` / `IJsonSerialize.ObjectToJSON` / `JSONToObject<T>` / `ICache.Get<T>` / `IToken.GetPrincipal` / `IXmlSerialize` now return nullable types. Callers with `<Nullable>enable</Nullable>` will see compiler warnings; add null-checks where appropriate.

## v1.2.2

- **Remote-service abstraction (breaking)**: lifted the provider-agnostic parts of `SyZero.Feign` into `SyZero.Core` under the new `SyZero.Client.RemoteService` namespace: `IRemoteServiceProvider` (service-level), `IRemoteServiceProxyFactory` (per-protocol), `RemoteServiceProxyFactoryManager`, `RemoteServiceOptions` / `RemoteServiceItem` / `RemoteServiceSetting` / `RemoteServiceProtocol`, plus the `services.AddRemoteService<TProvider>(...)` extensions.
- **`SyZero.Feign` is now a Provider**: `FeignServiceRegistrar` was rewritten as `FeignRemoteServiceProvider : IRemoteServiceProvider`, internally pre-registering the built-in `HttpProxyFactory` / `GrpcProxyFactory`. The old `FeignOptions` / `FeignService` / `ServiceSetting` / `FeignProtocol` / `IFeignProxyFactory` / `FeignProxyFactoryManager` types were removed in favor of the Core counterparts.
- **Config field renamed**: `Feign.Service[*].DllName` → `Feign.Service[*].AssemblyName` (semantics unchanged — the contract assembly name). Update your `appsettings.json` accordingly.
- **API shape preserved**: `builder.Services.AddSyZeroFeign(...)` keeps the same three overloads (parameter type changes from `FeignOptions` to `RemoteServiceOptions`); existing call sites only need a `using` / type-name update.
- **Dynamic API provider abstractions in Core**: introduced the `SyZero.Application.DynamicApi` namespace inside `SyZero.Core`, exposing provider-neutral helpers — `DynamicApiTypeFilter` (unified type-filter rules), `DynamicApiNameNormalizer` (length-descending postfix stripping + custom delegate), `DynamicApiAttributeCache` (cached attribute lookup), `DynamicApiAssemblyScanner` (system-assembly aware scanning + extra-exclude callback), `DynamicApiServiceCollectionExtensions`, `DynamicApiTypeHelper`, the `DynamicApiOptionsBase` abstract base class and the `IAssemblyDynamicApiOptions` marker interface. The duplicated `Helpers/ReflectionHelper.cs`, `Helpers/TypeHelper.cs`, and `Helpers/ServiceCollectionExtensions.cs` files inside `SyZero.DynamicWebApi` / `SyZero.DynamicGrpc` were removed and their code now delegates to Core. `DynamicWebApiOptions` / `DynamicGrpcOptions` now derive from `DynamicApiOptionsBase` while keeping their public properties unchanged (no breaking changes). New providers (e.g. GraphQL / MiniAPI / MCP server / JSON-RPC) can now be added in parallel using the same building blocks.
- **What it enables**: future remote-call providers (e.g. a WebApiClient/STJ-based lightweight one) can be added as siblings of Feign and consume the same `RemoteServiceOptions`.

## v1.2.1

- **New module [`SyZero.Gateway.YARP`](/en/modules/SyZero.Gateway.YARP)**: a second `IGateway` backend powered by [YARP](https://microsoft.github.io/reverse-proxy/) 2.3, sitting alongside `SyZero.Gateway.Ocelot`. One-line wiring with `AddSyZeroYarp(...)` + `await app.UseSyZeroYarpAsync()`. Shares the same `configuration.json` schema as Ocelot (`Routes` / `LoadBalancerOptions` / `ServiceName` etc.) and can be managed by the same `SyZero.Gateway.Admin` panel.
- **Unified service-discovery integration**: ships `SyZeroYarpServiceDiscoveryDestinationResolver` (YARP) and `SyZeroDiscovery` (Ocelot) — both built on the single `IServiceManagement` abstraction. Any backend that registers `IServiceManagement` (Consul / Nacos / Redis / Local / DB) plugs into both gateways transparently.
- **Instant churn feedback**: on first resolve the resolver subscribes via `IServiceManagement.Subscribe(...)` and emits an `IChangeToken`. When Consul/Nacos/Redis push a change, only the affected cluster's destinations are refreshed — no full configuration reload. `Dispose` cleanly unsubscribes.
- **Cross-backend LB mapping**: `GatewayLoadBalancerOptions.Type` (`RoundRobin` / `LeastConnection` / `NoLoadBalance`) is translated by `YarpConfigMapper` to YARP native policies (`RoundRobin` / `LeastRequests` / `FirstAlphabetical`), matching Ocelot semantics, so the same `configuration.json` swaps between backends.
- **Single source of truth for health**: health filtering is centralized in `IServiceManagement.GetHealthyServices(...)`. YARP / Ocelot do not run a duplicate active probe by default to avoid double-judging; native active probing can still be enabled via each backend's own configuration.
- **Docs**: zh + en module docs gained “Service Discovery” and “Load Balancing & Health Checks” sections for both `SyZero.Gateway.YARP` and `SyZero.Gateway.Ocelot`.
